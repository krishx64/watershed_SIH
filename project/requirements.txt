# Streamlit Community Cloud deploy manifest.
#
# Community Cloud just runs `pip install -r requirements.txt` (no separate
# pre-install step like the Dockerfile has), so unlike the main
# requirements.txt, torch/torchvision ARE listed here -- pinned to the same
# 2.6.0 / 0.21.0 pair already proven to work together (see requirements.txt's
# header for why an unpinned pair breaks segmentation-models-pytorch at
# import time), just the CPU wheel index instead of cu124.
#
# Measured locally with this exact CPU build: ~800MB peak RSS running the
# real pipeline end-to-end (import + model load + two full-AOI forward
# passes) against Community Cloud's ~1GB free-tier cap -- tight but workable
# for a low-concurrency demo. If it OOMs in practice, the fallback is
# Google Cloud Run with the project's Dockerfile (verified working, far more
# headroom) -- see documentation.md "Deployment".
#
# To use: on the `deploy` branch only, `cp requirements-streamlit-cloud.txt
# requirements.txt` before committing -- do not merge that swap into main.
