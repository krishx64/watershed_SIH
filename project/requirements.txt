# PS-26015 Watershed Signal — pinned dependencies.
#
# torch/torchvision are deliberately NOT listed below, and must be installed
# as an EXPLICITLY VERSION-PINNED PAIR, not just "latest from the CUDA index":
#
#   # Using uv:
#   uv pip install --reinstall torch==2.6.0 torchvision==0.21.0 --index-url https://download.pytorch.org/whl/cu124
#   uv pip install -r requirements.txt
#
#   # Using standard pip:
#   .venv/Scripts/python.exe -m pip install torch==2.6.0 torchvision==0.21.0 --index-url https://download.pytorch.org/whl/cu124
#   .venv/Scripts/python.exe -m pip install -r requirements.txt
#
# Two real failure modes hit in this project, both from getting this install
# wrong (see documentation.md for the full incident):
#   1. Plain `pip install -r requirements.txt` (or any other package pulling
#      torch in as a transitive dependency) silently grabs a CPU-only build
#      from the default PyPI index on Windows -- no error, inference just
#      quietly gets much slower.
#   2. Installing torch and torchvision UNPINNED (even both together, even
#      both from the CUDA index) can resolve to a mismatched pair -- e.g.
#      torch 2.6.0 + torchvision 0.29.0, which is not the version torch 2.6.0
#      actually ships against (0.21.0 is). The mismatch doesn't fail at
#      install time -- it fails later, at import, as
#      `RuntimeError: operator torchvision::nms does not exist`, when
#      torchvision's compiled extensions don't match the loaded torch ABI.
#      Explicit version pins on BOTH packages together is the only reliable
#      fix; re-verify with `pip list | grep torch` after any reinstall.
#
# If you ever see the app's header say "DEVICE: CPU" on a machine with an
# NVIDIA GPU, or an import-time `torchvision::nms` error, re-run the pinned
# install line above.

# Real watershed catchment/drainage delineation from DEM data (Copernicus
# GLO-30 via src/dem_fetch.py). Pulls in numba/llvmlite as a REQUIRED
# dependency (not optional, despite pysheds' own docs suggesting otherwise --
# checked via a real `pip install`, not assumed). pysheds 0.5 (latest on
# PyPI, checked) calls the now-removed `np.in1d`; src/watershed_delineation.py
# shims it to `np.isin` (numpy's own official replacement) before import --
# same class of fix as the segmentation-models-pytorch mismatches above, see
# documentation.md section 8.
#
# numba/llvmlite explicitly floored below: numba only added Python 3.14
# support in its 0.63.0 release (2025-12-08; llvmlite 0.46.0 alongside it).
# pysheds itself doesn't pin a numba version, so an unpinned install can
# silently resolve an older, incompatible pair on a platform running a very
# new Python -- this caused a real ModuleNotFoundError('pysheds') in
# production on Streamlit Community Cloud (Python 3.14), see
# documentation.md section 8. This is also why watershed_delineation's
# import is wrapped defensively in aoi_picker.py -- a missing/broken
# pysheds should degrade the watershed-boundary feature, not crash the app.
